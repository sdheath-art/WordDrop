# WordDrop — structural audit, 2026-10-20

Read-only audit. No code was changed to produce it. Three parallel passes:
level lifecycle · tile positions + resolution paths · pause owners + dead code.
**[V]** = verified by reading code or seeing it in a log. **[I]** = inferred from code, not seen running.

Why this exists: Spencer — *"how can we just get out of all these bugs? i feel like 100 percent
of them are coming from the old game build"*. Agreed direction: **rebuild the spine, keep the
body.** Not a rewrite. Keep all art, FX, UI, audio and tuning; replace split ownership.

---

## 1. The diagnosis in one paragraph

The bugs are not "old code is bad". They come from **many systems allowed to change the same
thing, at any moment, with nobody in charge**: board seeding has 3+ owners, tile positions have
16 live writers (6 of which each decide independently where a tile "should" be), the pause is one
bool with 9 writers where last-write-wins, "what phase is the level in" is spread across ~12
flags in 6 files, and there are 8 copies of "what happens after a word resolves" (4 dead, 4 live,
and the live ones disagree with each other). Drop-era code makes it worse because it is still
partly running and nobody can tell which parts.

## 2. Size

86k lines. Rough split (±15%, [I]):
- **Core** ~57–60k (68%)
- **Dead with current flags** ~17–19k (21%) — hand/drop turns, AI playback, Level/Daily stack, tests
- **Live but legacy** ~8–10k (11%) — still runs in the swap game though built for the drop game

## 4. The restructure — four owners, in recommended order

Each step leaves the game playable. Spencer playtests between steps. Compile check after every batch.

### Step 1 — LevelLifecycle (fixes 1, 5, 7, 10, 13, 14 and the "two boards" family)
One state machine; everything else asks it instead of keeping its own flag.
```
Idle → Installing → Briefing(home+card) → Entering → Playing → Won(resolving tail) → Celebrating(modal+exit) → Installing…
                                                        ↘ ToppingOut → Playing | GameOver
```
Derived answers that replace scattered flags:
`InputOpen = Playing` · `RisesAllowed = Playing` · `BoardSeedAllowed = Installing && board off-screen` ·
`TimersFrozen = !Playing` · `InvariantsActive = Playing || Celebrating`.
- `CheckStageClear` → `Lifecycle.TargetReached()` (replaces `AwaitingNextLevel`; rises stop instantly)
- `StageClearModal` Show/Dismiss → `Celebrate()` / `RequestNext()` (replaces ObjectiveManager's retire-edge as the install trigger)
- `Lifecycle.Install(n)` is the ONLY caller of board seeding (OpeningSeed / LevelRules / ObjectiveManager board part); clears pending rises; resets LevelRules statics per run; runs AFTER the exit slide
- Entry slide completion → `EntryDone()`, with a watchdog timeout
- Gates read it: UpdateSurvival (Starved/pending/clock), WaitAndExecuteRise, ExecuteRisingRow, HandManager gate + TryTapDetonate, SwipeWordInput, BoardInvariants, ObjectiveManager.Update

### Step 2 — Pause owner-set (fixes 4-adjacent, 6; small: 17 writes in 9 files)
`HashSet<string> _pauseClaims`; `AcquirePause(owner)` / `ReleasePause(owner)`; paused = set non-empty;
logs `[Pause] +owner` / `-owner`. `SetOverlayPaused(bool)` kept as a shim (claim "legacy") during migration.
Owners: StageClear, LevelIntro, LevelMap (gains a release in FadeMapOut/HardReset), Settings, Continue,
Unlock, BoosterChoice, TutRise/TutTopOut/TutDecay, TopOut. Much of this folds into Step 1 (pause derived from phase).

### Step 3 — Quarantine the drop game (no behaviour change; makes everything after it smaller)
Behind one define `WORDDROP_DROP_LEGACY` (OFF), moved as ONE unit because the pieces call each other:
hand drag/drop + FullTurnSequence, stamp/rewrite, card UI/shuffle/bag, GameVisualBridge AI playback,
MatchController drop/AI, old cycle tutorial, Meltdown, Replay/Recorder, BonusMode, BoosterChoice,
DropPreview/ColumnArrow/MatchManager, retired LevelTable rows, Vault/HeroWord/HiddenWord objectives.
**Kept but quarantined, not deleted** (Spencer's rule): the Level/Daily stack (daily leaderboard is a
locked future feature), LevelMap walking code (HomeMode switch).
**Safe to actually delete** (zero callers): `RulesEvents.cs`, `TryLegalSwap`/`SwapResolutionSequence`,
`WordDropFX.PlayHitStop`, `SurvivalManager.ExecuteAutoDrop`.
Tests (`RulesEngineTests`, verification methods) → Editor/test assembly.

### Step 4 — One ResolutionRunner (fixes 2, 11, 12)
Live today: Tap, Swap, Swipe, BoosterCascade. One `Run(request)` coroutine:
gate (try/finally) → prime initial words (ONE priming function) → NextStep loop → Explode = defrost +
deposit + FX + remove → ONE gravity (the events-based one that reconciles) → finalize (`ticksTurn`) →
sync → move accounting → stage-clear check. **Payment only in Explode**, so form-time pay is impossible
by construction. Migrate: swipe → swap → booster → tap (most tuned, last; diff `[ScoreLag]`/`[ArmedWeb]` log lines before/after).

### Step 5 — TilePresenter (fixes 8, 9)
Position = `CellToWorld(cell) + slideOffset`, always. Every motion requested through it with an owner;
shakes/punches/ripples become ADDITIVE offsets, not absolute writes. Per-channel claims (position vs
scale) so a squish can't release a fall. One `Settle(tile)` replaces the six independent snappers;
BoardInvariants reports and asks the presenter to settle.
Cheapest high-value first: per-channel claims → slide offset in the two snappers → additive FX → collapse snappers.
